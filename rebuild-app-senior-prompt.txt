4. DESIGN DIRECTION
================================================================================

4.1 CONCEPT
"Editorial terminal portfolio": the precision of a developer tool, the warmth of
an editorial magazine, and the calm of a dark studio.

Think: large confident type, generous negative space, a restrained purple accent,
fine grid lines, glassy surfaces, code-inspired micro-details (#, brackets,
status dots), and one memorable hero composition. Avoid a generic "purple
gradient SaaS" look, neon gamer styling, glassmorphism everywhere, and gratuitous
animation.

4.2 COLOR SYSTEM
Keep the supplied palette as the foundation, but introduce semantic tokens so
components never guess:

  Canvas:        #282C33  (--color-canvas)
  Canvas deep:   #1E2229  (--color-canvas-deep)
  Surface:       #2E333C  (--color-surface)
  Surface raised:#343A44  (--color-surface-raised)
  Border:        rgba(255,255,255,0.10) (--color-border)
  Border strong: rgba(199,120,221,0.35) (--color-border-brand)
  Text:          #FFFFFF  (--color-text)
  Text muted:    #ABB2BF  (--color-text-muted)
  Text faint:    #7F8794  (--color-text-faint; only for non-essential labels)
  Brand:         #C778DD  (--color-brand)
  Brand strong:  #A855C8  (--color-brand-strong)
  Brand soft:    rgba(199,120,221,0.12)

Contrast rules:
- Body text must be >= 4.5:1 against its surface. Do not use opacity below ~70%
  for body copy.
- Use dark text (#1E2229) on solid brand purple buttons for readable contrast.
- Use brand text on dark surfaces, not white text on #C778DD, unless the size
  is large and contrast is verified.
- Borders are separators, never the only indicator of state.

Recommended @theme additions (Tailwind v4):
  --color-canvas, --color-canvas-deep, --color-surface, --color-surface-raised,
  --color-border, --color-border-brand, --color-text, --color-text-muted,
  --color-text-faint, --color-brand, --color-brand-strong, --color-brand-soft
Keep legacy aliases only if needed during migration, then remove them.

4.3 TYPOGRAPHY
- Font: Chivo Mono, weights 400/500/600/700/800, display swap.
- Display: clamp(2.75rem, 6vw, 5.5rem), line-height 0.98-1.05, letter-spacing
  -0.04em, text-wrap: balance.
- Section headings: clamp(1.75rem, 3vw, 2.5rem), weight 700.
- Body: 0.9375-1.0625rem, line-height 1.65-1.8, max-width 65ch.
- Eyebrow/label: 0.6875-0.75rem, uppercase, letter-spacing 0.18em, muted.
- Code/terminal details: 0.75-0.875rem, muted, with brand punctuation.
- Use tabular numerals for years/counts if supported.

4.4 SPACING, GRID, SURFACES
- Base spacing unit: 4px; use an 8px rhythm.
- Container: max-w-6xl (72rem), px-5 sm:px-8 lg:px-12.
- Section vertical padding: py-16 sm:py-20 lg:py-28.
- Radius: 6px controls, 12px cards, 20px feature panels, full for pills.
- Borders: 1px rgba(255,255,255,0.10); hover: brand-tinted.
- Shadows: soft ambient only; no giant colored glows on text.
- Surfaces: bg-surface/60 with border and optional backdrop-blur; use sparingly.
- Grid background: very subtle, masked, non-interactive, aria-hidden.
- One container width everywhere, including header/footer.

4.5 MOTION
- UI transitions: 150-250ms, ease-out.
- Hover lift: translateY(-2px) maximum; no bouncing.
- Page/section entrance: one subtle fade-up, 400-600ms, staggered by CSS delay.
- Nav/mobile panel: 250-350ms opacity/transform/height.
- Background atmosphere: slow, transform/opacity only; disable on mobile and
  reduced motion.
- Respect prefers-reduced-motion: reduce for every animation and transition.
- Do not animate layout properties except the mobile menu height.

4.6 VISUAL MOTIFS
- Fine 1px rules, corner brackets, small hash prefixes, status dots.
- Project covers generated with CSS gradients + grid/pattern + large initials or
  abstract shapes. No stock photos, no missing files.
- Portrait: either a real optimized image (if the owner adds one) or a designed
  monogram card with a terminal/code treatment and a status badge.
- Keep decorative elements aria-hidden.

7. SHARED PRIMITIVES - REQUIRED BEHAVIOR
================================================================================

7.1 cn()
A tiny local helper:
  export function cn(...classes: Array<string | false | null | undefined>) {
    return classes.filter(Boolean).join(" ");
  }
Use it for conditional classes. Never render "undefined" into className.

7.2 AppLink (critical)
A typed link abstraction that chooses the correct element:

  type AppLinkProps =
    | { to: string; hash?: string; children: ReactNode; ...internal props }
    | { href: string; external?: boolean; children: ReactNode; ...anchor props }

Behavior:
- Internal paths (starting with "/") -> TanStack Router <Link>.
- Internal hash-only (starting with "#") -> <a href="#..."> or a Link with hash,
  but never reload the page.
- http(s) -> <a href target="_blank" rel="noopener noreferrer">.
- mailto: -> <a href="mailto:..."> (no target="_blank").
- Render decorative icons as aria-hidden.
- Add an accessible new-tab hint via visually hidden text or aria-label.
- Do not use casts such as `as "/"`.

Use AppLink in Header, Footer, socials, project links, contact, and CTAs.

7.3 ButtonLink
Supports primary/secondary/ghost variants, sizes, icon, external/internal via
AppLink. Must be a real link (or button when performing an action), with visible
focus-visible ring, disabled styles if applicable, and 44px minimum touch target.

7.4 SectionHeading
- Renders an h2 by default, with optional eyebrow and description.
- Decorative "#" and rules are aria-hidden.
- Uses theme tokens, not inline colors.
- Consistent bottom spacing.

7.5 Container
- One max-width and responsive horizontal padding used everywhere.
- No nested containers creating double gutters.

7.6 Icon
- Keep a typed icon-name union.
- Prefer inline SVG path components over dangerouslySetInnerHTML. If keeping the
  static string map, keep the existing safety comment and never accept user HTML.
- Default aria-hidden="true". Provide an optional title only when the icon is the
  sole accessible label (otherwise label the parent control).

7.7 Reveal (optional)
- CSS-only entrance using opacity/translate and animation-delay.
- Must be disabled under reduced motion and must not cause layout shift.
- No IntersectionObserver unless it provides clear value.

- One h1 "Selected work" or "Projects".
- Short intro and count (e.g. "03 projects").

  links.

  each in the sitemap exactly once.

- h1 "About me".

  rather than inventing employers).

- CTA to contact.

9.5 CONTACT (/contact)
- h1 "Let's work together" or "Contact".
- Strong email CTA using site.email; optional copy-email button with clipboard
  fallback and an aria-live confirmation.
- Availability, location, response expectation.
- Social links with correct external/mailto behavior.
- No fake contact form unless it actually submits. A mailto form is not a
  reliable product; prefer a direct email CTA.
- Clear focus states and 44px targets.

9.6 404 / ERROR
- In-app notFoundComponent and errorComponent matching the design.
- Static public/404.html updated to match the visual language.
- Links: Home, Projects, Contact.

11. ACCESSIBILITY CHECKLIST
================================================================================
- Semantic landmarks: header, nav, main, footer; one main per page.
- Skip link is first focusable and moves focus to main.
- All controls reachable and operable by keyboard; no positive tabindex.
- Focus-visible ring: 2px brand + 2px offset (or equivalent high-contrast style).
- Active nav links have aria-current="page".
- Mobile toggle: aria-label, aria-expanded, aria-controls; icon aria-hidden.
- Closed mobile panel: inert + aria-hidden.
- All images have meaningful alt text; decorative images alt="".
- All icon-only controls have accessible names (aria-label or visually hidden).
- External links announce new-tab behavior.
- Color contrast: body >= 4.5:1; large text >= 3:1; UI boundaries >= 3:1.
- Touch targets >= 44x44 CSS px, with adequate spacing.
- Text remains readable at 200% zoom and 320px width.
- Reduced motion disables all non-essential animation.
- No heading levels skipped.
- No content conveyed by color alone.
- If a form/copy button exists: labels, error messages, aria-live feedback.

================================================================================
- Do not add packages "to save time".
- Do not keep the old components and sprinkle gradients on them.
- Do not use text-current / bg-current / border-current as design tokens.
- Do not use opacity below 70% for body text.
- Do not hide primary desktop navigation until hover.
- Do not use href="#" as a placeholder.
- Do not reference missing images or assets.
- Do not use `as any` or unsafe route casts for external links.
